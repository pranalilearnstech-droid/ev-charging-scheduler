🧮

AOA — Algorithm Design & Analysis

Smart allocation driven by algorithmic paradigms ensuring optimal slot assignment with minimum wait time and maximum throughput.

ALGORITHMS USED
  • ▸Greedy Algorithm — Assigns nearest available charger instantly
  • ▸Dijkstra's SSSP — Shortest path from EV to charger hub
  • ▸Priority Queue (Min-Heap) — Orders EVs by battery urgency score
  • ▸Dynamic Programming — Optimises multi-slot energy cost globally
  • ▸BFS / DFS Traversal — Network topology discovery
O(n log n)Min-HeapGreedyDPDijkstra
🌐

CN — Computer Networks

All communication between EVs, chargers, and the central server uses networking principles for reliable, low-latency real-time coordination.

NETWORKING CONCEPTS
  • ▸TCP/IP Stack — Reliable slot-booking request transport
  • ▸MQTT Protocol — Lightweight IoT pub/sub charger telemetry
  • ▸REST API / WebSocket — Real-time bidirectional EV-server link
  • ▸Subnetting & VLANs — Network segmentation per charging zone
  • ▸QoS & Congestion Control — Priority packets for emergency EVs
TCP/IPMQTTWebSocketQoSVLAN
🖥️

OS — Operating Systems

The backend server leverages OS-level resource management to handle concurrent charging requests, preventing deadlocks and starvation.

OS CONCEPTS APPLIED
  • ▸Process Scheduling (RR/Priority) — Fair slot queuing
  • ▸Semaphores & Mutex — Prevents double-booking of same port
  • ▸Banker's Algorithm — Deadlock avoidance / safe state check
  • ▸Virtual Memory / Paging — Session & slot data management
  • ▸IPC (Inter-Process Communication) — Charger-server signalling
SemaphoreBanker'sSchedulingIPCMutex
System Design

Full-Stack Architecture

Frontend → Network Layer → Backend Server → Allocation Engine — every tier maps to a CS discipline.

🖼️ Frontend Layer

1
EV user opens web app / mobile dashboard
↓ HTTP/HTTPS Request (CN — TCP/IP)
2
Sends: battery %, GPS location, charger type
↓ WebSocket connection (CN)
3
Real-time map shows available chargers via REST API
↓ User confirms booking
4
POST request triggers backend allocation pipeline

⚙️ Backend Engine

1
Request received by Node.js server process
↓ OS Round-Robin / Priority Scheduler
2
Mutex lock acquired on target charger port (OS Semaphore)
↓ AOA — Min-Heap + Dijkstra Algorithm
3
Optimal charger selected by distance + urgency score
↓ Banker's Algorithm safety check (OS)
4
Slot confirmed → IPC signal → charger activates

🌐 Network Topology (CN)

1
EV App ↔ Cloud Server via TLS 1.3 encrypted tunnel
2
MQTT broker collects charger telemetry (voltage, temp)
3
Each charging zone on separate VLAN — isolated failure domain
4
QoS DSCP EF: emergency low-battery packets get priority

🧮 AOA — Allocation Detail

1
Build adjacency graph of all zone chargers (BFS)
2
Insert EVs into Min-Heap keyed by urgency = (100 − battery%)
3
Dijkstra finds lowest-cost path EV → available charger
4
DP minimises total energy cost across all simultaneous assignments
